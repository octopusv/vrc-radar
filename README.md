# VRC Radar

VRCXのローカルデータベース（`%APPDATA%\VRCX\VRCX.sqlite3`）を読み取り専用で参照する
Webダッシュボード。フレンドがいまどのインスタンスにいるかを一望できる。

- **現在地** — フレンドがいるインスタンスを人数の多い順に表示（VRCXのフレンド現在地タブ相当）
- ダッシュボード（オンライン状況・アクティビティ推移・滞在時間ランキング）
- フィード（移動 / オンライン・オフライン / ステータス / アバター / bio）。
  行の矢印で詳細を展開: アバターは変更前後のサムネイル画像、移動は
  どこから→どこへ（移動元の滞在時間つき）、ステータス/bioは変更前後
- フレンド一覧（プロフィール画像・現在地・Trust・最終確認・お気に入りグループ絞り込み）
- ユーザー詳細（相互フレンド、アバター履歴、セッション時間、メモ）
- ゲームログ（自分のインスタンス履歴）／フレンド相関グラフ／グループ通知
- マルチアカウント（URL `/1`, `/2`, … で切替）
- PC / スマホ両対応（スマホはボトムナビ。ホーム画面に追加してPWA風に使える）
- `/dev` はデモページ — すべて架空のデータで同じUIが動くので、
  実際のフレンドを映さずに機能を紹介できる

## お気に入り（★）

★は **VRChat本体のフェイバリットグループ** の登録内容。VRCXが保存している認証Cookieを
そのまま再利用して VRChat API から読み出す（GETのみ・10分キャッシュ）。

- Cookieは `api.vrchat.cloud` への `Cookie` ヘッダーにのみ使用し、ログにも
  レスポンスにも一切出さない。
- グループ名はVRChat側で付けた表示名。未設定なら「グループ1/2/3」と表示する。
- VRCXで再ログインが必要な状態になると各ページに警告バナーが出る。

## 実行

依存パッケージなし（Python 3.11+ 標準ライブラリのみ）。

```powershell
python main.py            # PORT 環境変数で待受ポート指定（既定 8321）
```

- `VRCX_DB` 環境変数で既定DBパスを上書き可能。
- `VRC_RADAR_UA` でVRChat APIに送るUser-Agentを変更可能。
- VRCXのDBは常に `mode=ro` で開く。書き込むのは `image_cache/`
  （アバター画像の実体保存。拡大表示した高解像度版も含めて残すので、
  VRChat側で消えても履歴の画像が失われない）だけで、消してもキャッシュが飛ぶだけ。
- ヘルスチェック: `GET /health`

## マルチアカウント

アカウントは自動検出される: 設定された各DBファイル内の `usr…_friend_log_current`
テーブルごとに1アカウント。`/1` が既定DBの現行アカウント。

2アカウント目を**同時に**追跡したい場合は、VRCXをデータディレクトリ分離で多重起動する:

1. ショートカットを作成: `"C:\Program Files\VRCX\VRCX.exe" --config="C:\VRCX2"`
2. そのVRCXで2つ目のアカウントにログイン（DBは `C:\VRCX2\VRCX.sqlite3` にできる）
3. このディレクトリに `accounts.json` を作成:

```json
[
  { "db": "C:\\VRCX2\\VRCX.sqlite3", "label": "サブ垢" }
]
```

再起動不要（60秒以内に自動検出）。サイドバーに切替UIが出て、`/2` でアクセスできる。

なお★お気に入りは、そのDBで**現在ログイン中**のアカウントでのみ取得できる
（Cookieがそのアカウントのものであるため）。

## 注意

- フレンドの行動履歴という個人情報を扱うため、インターネット越しに使いたい場合は
  必ず認証付きのリバースプロキシ等の背後に置くこと。認証なしで公開してはいけない。
- データの鮮度はPC上でVRCX本体が起動していることに依存する。
- 「現在地」はVRCXが受信した最新イベントからの推定。VRCX停止中の移動は反映されない。
- VRCXのDBスキーマ（`usr<hex>_feed_*` 等）に依存しているため、VRCXのメジャー更新後に
  表示が壊れた場合は `main.py` のテーブル参照を確認する。
